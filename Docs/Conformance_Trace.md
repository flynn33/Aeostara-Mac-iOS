# macOS native conformance trace

This trace maps frozen source rules to the native macOS implementation and concrete tests. The coordinated release record supplies the final source commits, executed command receipts, archives, binary-consumer results and gate judgments. This document does not substitute source tests for archive or extracted-binary evidence.

The exact authorities are Aeostara base `774b981ef2267a41c1b1a59497b2b0746a86f32b`, ASH Pattern System `e123f5d7fdbb381179971f721a3292c31eb1cbc2` and raven-forge-development `8dd6e75a06336491b249fac3577db75458db8c13` (policy 0.7.0). Source authorities, the producer CLI, tests, fixtures and rich development recorder remain outside the SDK runtime closure.

Domain exports `AeostaraContract`, canonical `ContractCoding`/`JSONValue`, explicit `SemanticContext`, `NativeSemanticProjector`, `NativeAshBindingProvider` and pure `NativeHealingEngine`. Services exports scoped native `NativeHealingService`, resource, policy and containment bindings, lean release recording and paired export. Callers declare immutable recognized-state, full-intent, mapping, transition, predicate and generation registries. The SDK never guesses application semantics from arbitrary JSON.

The canonical contract decoder retains raw numeric tokens until typed integer admission. Foundation `Codable` remains an interoperability path whose decoder does not expose the original numeric lexeme; exact contract admission uses `ContractCoding`.

## Conflicts, bounds and evidence scope

The base `CanonicalCodewordSet` example contains vectors 0...15, conflicting with the ASH canonical [9,4,4] set. Its original bytes remain codec input only; native semantics use the exact ASH set and reject other codewords. Sparse source scenarios containing the same empty observed/desired documents cannot provide absent projection context. Actual native tests bind explicit immutable contexts and concrete evidence; they do not dispatch on fixture ID, category or expected output.

Frozen failure DTOs such as `MappingResult` require a complete projected state even when evidence is missing. The explicit Swift failure channel therefore throws `LifecycleFailure` with the actual envelope/chain and optional actually persisted audit. It never invents a nine-coordinate state, backup record or restored hash for unavailable evidence.

ASH depth-zero topology has one root and zero edges, while frozen base `TopologyPlan.edges` requires at least one edge. The current macOS operation diagnoses that request as unavailable evidence, without fabricating an edge or claiming depth-zero serialization conformance. Explicit native contexts admit depths one through eight for produced plans. The coordinated release record retains this source-contract limitation and its review disposition.

Native snapshots and publication are bounded at 16 MiB per resource. Oversized configuration, backup and audit append are rejected before publication. Locks use canonical resource paths and retained native `flock` descriptors with named inode checks. Root, parent, lock namespace, staging and named resource identities are checked around mutation. Actual tests exercise moved-parent, stale-byte, hardlink, alias and independent-instance cases. Advisory locks do not constrain uncooperating writers; filesystem checks cannot promise atomic exclusion of owner-controlled directory changes between a check and a syscall.

The 28-case finite numeric canonical corpus checks actual bytes from the pinned base implementation; it is bounded numerical evidence, not an exhaustive proof for every IEEE-754 value. Unsupported nonfinite or resource-exhausting numbers fail explicitly. Source validation, native Debug/Release tests, iOS simulator tests, library-evolution archives, binary-only consumers and published downloads have separate scopes and receipts. The release record reports which exact candidate checks were actually executed and accepted.

The normal source commands are `swift test`, `swift test -c release`, and `python3 ci/acceptance_runner.py <built-cli> fixtures fixtures/cli_semantic_context.template.json`. The CLI template is an explicit consumer-owned example, with its resource root bound separately to each isolated scenario. Context-free invocation fails before mutation; applications must supply actual projection context and policy.
