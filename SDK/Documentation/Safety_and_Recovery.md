# Safety and recovery

The consuming application owns its authorized configuration scope, desired intent, policy, consent, lifecycle and presentation. Aeostara has no authority to scan arbitrary directories or invent a valid state. Keep external writers outside an active healing operation; leases coordinate cooperating native adapters, and stale byte identities reject changed input.

Before mutation, supply a complete semantic context and an actual policy registry/bundle. Missing or malformed requested policy input fails closed. Stable/no-action paths still evaluate provided policies. A policy denial produces no configuration mutation or backup. Optional diagnostics do not replace mandatory durable audit. Audit persistence and verified exclusive backup must succeed before a write. Existing backup bytes are preserved on collision.

Native resource validation rejects destinations outside the declared root, hard-link aliases, colliding resource identities and unsafe traversal. Symbolic aliases that resolve to the same authorized resource share the lease identity. Export roots are stricter: use a private existing canonical directory without intermediate symlinks. Native files use anchored descriptors, exclusive creation and identity checks.

Plans bind observed and desired canonical hashes before execution. Replacement checks the expected stored bytes. Verification re-observes actual content and semantic state. Rollback success requires exact restoration and verification; false, thrown, partial and wrong-byte restoration remain failures. Preserve the originating failure even when recovery fails.

Fallback candidates require explicit applicability, known-valid recognition, validation and deterministic rank/policy ordering. A valid fallback may cross an orbit when the governing recovery policy authorizes it. Unavailable fallback moves to declared containment and then terminal safe halt when its obligations cannot be established. Contained instances permit only their declared restricted operations; they cannot resume arbitrary mutation. Reentrant execution and replayed/foreign preparation tokens fail.

Source fault-injection tests exercise failure boundaries; final binary fixtures exercise the public consumer route. Neither establishes immunity to non-cooperating kernel-level races, device loss or every filesystem. See the coordinated guide for the actual tested cases and limits.
