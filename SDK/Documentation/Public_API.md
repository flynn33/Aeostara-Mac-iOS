# Public API

`AeostaraMacDomain` owns immutable contracts, canonical JSON, explicit semantic context, ASH binding and lifecycle planning. `AeostaraContract` contains the 59 DTO shapes from the frozen base schemas. Platform-owned coding boundaries validate required fields and enum/type constraints; missing evidence is a typed failure, not a fabricated diagnostic or proof. Contract JSON member names follow the frozen schema, independently of Swift spelling. `AuditEvent.eventSequence` uses `ContractInteger` to preserve the schema’s unbounded integer range; `intValue` is optional when a caller needs a machine-sized integer. Integral decimal JSON values are admitted where the schema requires an integer.

The canonical JSON layer retains raw UTF-8 key identity, ordered arrays, Boolean versus number, null versus missing, and JSON Pointer token boundaries. Document identities use SHA-256 over canonical bytes. Provide source references with observed snapshots and desired intent. Do not bridge arbitrary configuration through lossy dotted paths or infer meaning from `NSNumber`.

`SemanticContext` registers caller-owned mappings and known-valid facts. A mapping must have one defined result and a matching source-bearing rule; absent or ambiguous context fails before mutation. ASH uses the verified nine-coordinate code, all 16 frozen codewords, and 32 orbits. Generation, topology, transition validation, classification, diagnostic chains and recovery selection use the frozen authorities. A state in an orbit alone does not establish an authorized correction.

`AeostaraMacServices` supplies native filesystem/resource adapters used by Domain’s public `NativeHealingService` orchestration. Dry-run/planning is observation-only. Healing evaluates supplied policy, acquires a resource lease, persists mandatory audit, creates and verifies an exclusive backup, executes the prebuilt plan, and verifies actual resulting bytes. Recovery receipts distinguish successful mutation, exact rollback, fallback, containment and halt. A failed restore must not be reported as successful rollback.

The diagnostic API is a separate typed contract in Domain: closed stages/outcomes/fault codes, UUID identities, causal links, limits, immutable snapshots and health counters. Services supplies `ReleaseDiagnosticRecorder` and `DiagnosticExporter`. The rich development recorder is an internal source target and is absent from both public products and framework targets. No `@testable import` is needed by the binary consumers.

See [Migration](Migration.md) for necessary safety changes and the source branch `Docs/Conformance_Trace.md` for exact implementation/test mappings. The source tests and binary consumer tests are separate evidence classes, recorded in the coordinated release guide.

The pinned ASH topology rules permit depth zero with one root and no edges, while the frozen base `TopologyPlan` schema requires at least one edge. This release reports a diagnostic-bearing contract failure for depth zero; it does not invent an edge or change the frozen schema. Successful topology serialization covers supported positive depths, with exact cases recorded in the native conformance trace.
